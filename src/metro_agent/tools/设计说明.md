# Agents_tools 设计说明

## 职责与边界

`Agents_tools` 是 Agent 可调用工具、RAG 链路工具、Obsidian 离线索引构建和离线评测入口的集合。它连接知识库文件、向量索引、工具执行、评测数据和上层 Agent 编排，是当前项目里“能力工具层”的主要承载位置。

本目录不负责 Web API 路由、前端页面渲染、数据库迁移或 trace 数据模型。在线链路的调用记录由 `observability` 负责，长期对话历史由 `conversation_history` 负责，离线评测编排的高阶运行器放在 `evaluation`。

## 主要组件

- `Knowledge_RAGtools.py`：RAG 查询工具入口，读取已发布的 Obsidian 索引并返回检索结果、引用文档和检索分数。
- `obsidian_loader.py`：加载 Obsidian 生成的 Markdown 文件，处理 frontmatter、链接、标签、标题层级等文档结构。
- `build_obsidian_index.py`：离线预构建索引脚本，负责 staging、发布、回滚和异常状态恢复。
- `chunk_artifacts.py`：把文档切分结果、预览文件和 manifest 产物落盘，便于人工检查切分效果。
- `knowledge_index_registry.py`：维护已发布索引的注册信息，保证线上 RAG 只读取明确发布的版本。
- `rag_evaluation.py`：确定性 RAG 基线评测入口，读取金标集并输出检索指标与 case 结果。
- `ragas_evaluation.py`、`deepeval_agent_evaluation.py`：兼容入口，连接到 `evaluation` 下的 RAGAS 和 DeepEval 运行器。
- `Realtime_tools.py`：实时类工具封装，用于外部实时信息能力或测试 mock 链路。

## 数据流与生命周期

Obsidian 文档从本地 Markdown 进入 `obsidian_loader.py`，经切分后由 `build_obsidian_index.py` 写入向量库的临时 collection，并生成 chunk artifact。发布成功后，`knowledge_index_registry.py` 将当前生效 collection 与 build id 写入注册表。

在线 RAG 查询时，`Knowledge_RAGtools.py` 只读取注册表指向的已发布索引。它返回文档名、chunk id、rank、score、引用等检索证据，不应把完整 chunk 文本写进 trace。

离线评测时，`rag_evaluation.py` 从金标集出发，读取已发布 chunk manifest 和索引结果，输出 `case_results.jsonl`、`summary.json`、`report.md` 等评测产物，供后续 RAGAS 和 DeepEval 使用。

## 依赖与配置

本目录依赖 LlamaIndex、Chroma 或项目当前向量存储、Obsidian Markdown 文件、模型配置和本地产物路径。云端 LLM 裁判或 embedding 配置不应硬编码在工具文件中，应通过环境变量或项目配置注入。

发布索引时要依赖 `D:\AIKnowledge\wiki` 或配置指定的知识库目录、`chroma_db` 等本地资源。所有密钥均通过环境变量读取，不写入产物和日志。

## 持久化与产物

主要持久化对象包括：

- 向量索引 collection。
- 已发布索引注册信息。
- `artifacts/chunks/` 下的切分预览、JSONL 和 manifest。
- 离线评测输出目录中的 case 结果、指标汇总和报告。

构建索引应采用先 staging、再 publish 的生命周期。失败时记录 `failed` 或 `publish_uncertain` 状态，后续通过 reconcile 命令收敛到发布或回滚。

## 异常处理与测试策略

索引构建失败不能污染线上已发布索引。发布状态不确定时，应保留恢复入口，避免直接覆盖注册表。RAG 查询失败时，应返回可诊断错误，并让上层 Agent 决定是否降级回答。

测试应覆盖 Obsidian 加载、chunk artifact 生成、索引注册表发布规则、RAG 查询返回结构、离线评测指标计算和异常状态恢复。涉及外部模型的测试应使用 mock 或允许降级跳过。

## 维护建议

新增工具时先判断它是在线 Agent 工具、离线构建工具还是评测工具，并放到清晰入口中。在线工具必须考虑 trace 记录、超时、错误分类和 token 成本归集。

不要让线上查询链路在请求时重建 Obsidian 索引。知识库变更应先离线构建、人工检查 chunk artifact，再发布为线上可读版本。
