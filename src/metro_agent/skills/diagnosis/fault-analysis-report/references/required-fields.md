# 故障分析报告 — 必要字段清单

本文档定义生成一份完整、合规的故障分析报告所需的最低信息要求。

Agent 在开始生成报告前，必须对照此清单检查信息完整性。

---

## 一、必要字段（缺失时**必须**反问用户）

以下字段是报告的“骨架”，缺少任何一项，报告都不完整。Agent 应主动生成澄清问题，并在用户补充前**不生成正式报告**。

| 字段 | 说明 | 反问示例 |
| :--- | :--- | :--- |
| **故障发生时间** | 具体日期和时间（精确到分钟），或时间段 | “请问故障发生的具体时间和结束时间是什么？” |
| **故障设备/系统名称** | 设备编号、系统名称或关键部件名称 | “请问是哪个设备或系统出现了故障？（如 11号线赤沙站时钟系统）” |
| **故障现象** | 用户/系统观察到的具体异常表现 | “请问故障的具体现象是什么？（如 主时钟源异常告警、时钟同步失败）” |

## 二、强烈建议字段（缺失时**标注“未提供”**）

以下字段能大幅提升报告的完整度和参考价值。如果用户未提供，Agent 应在报告对应位置标注“未提供”或“待补充”，**但不阻塞报告生成**。

| 字段 | 说明 | 报告中的标注方式 |
| :--- | :--- | :--- |
| **影响范围** | 受影响的线路、车站、业务或用户群体 | “影响范围：未提供” |
| **处置过程** | 故障发生后采取的处理步骤和时间节点 | “处置过程：未提供” |
| **初步原因分析** | 根据现有信息作出的初步判断 | “初步原因：未提供” |
| **关键测试数据** | 故障期间的设备指标、日志片段或测试结果 | “测试数据：未提供” |
| **故障影响时长** | 从故障发生到恢复的总时长 | “故障影响时长：未提供” |
| **处理人员** | 参与故障处理的人员姓名或工号 | “处理人员：未提供” |
| **相关变更记录** | 故障前是否有变更操作 | “相关变更记录：未提供” |
| **截图/附件** | 告警截图、拓扑图、波形图等 | “截图/附件：未提供” |

---

## 三、可选字段（有则提供，无则不写）

以下字段属于“锦上添花”，不强制要求，也不需要在报告中标注缺失。

| 字段 | 说明 |
| :--- | :--- |
| 告警编号 | 网管系统产生的相关告警ID | “关联告警：未提供” |
| 厂家/技术支持意见 | 设备厂家或二线支持的反馈 | 
---

## 四、字段优先级与Agent行为规则

| 优先级 | 字段类别 | Agent行为 |
| :--- | :--- | :--- |
| P0（阻塞） | 必要字段 | 缺失时反问用户，不生成报告 |
| P1（高） | 强烈建议字段 | 缺失时在报告中标注“未提供”，继续生成 |
| P2（中） | 可选字段 | 有则写，无则不写，不标注缺失 |

---

## 五、信息收集的最佳实践

1. **一次性收集**：在首次反问时，使用清单模板一次性列出所有缺失的必要字段，避免多轮拉扯消耗Token。
2. **结构化追问**：如果用户补充的信息仍不完整，只追问缺失部分，不重复已提供的内容。
3. **适度推断阈值**：当用户连续两次补充后仍缺失同一字段，不再追问，标注“待补充”并生成报告。
4. **记录来源**：最终报告中的每个事实性陈述，应在内部记录其来源（用户提供/系统查询/知识库引用），便于可追溯。
