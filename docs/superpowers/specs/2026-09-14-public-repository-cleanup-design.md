# 公开仓库清理与同步设计

## 目标与边界

本次交付将本地 `master` 已提交的内部试点能力同步到 GitHub `origin/master`，并清理受版本控制的源码与运行配置中的普通说明注释，使公开仓库更接近当前交付状态。

清理范围仅限受 Git 跟踪的 `.py`、`.js`、`.css`、`.yml`、`.yaml`、`.toml`、`.sh`、`.ps1` 和 `Dockerfile`。不修改 `README.md`、`docs/`、许可证、历史提交或未跟踪的交接文档。不会自动提交 `.env`、临时 pytest 目录、缓存、worktree 或其他未被明确识别为可安全删除的用户文件。

## 注释清理规则

删除独立的普通解释性注释和不承载工具语义的行尾解释。保留 shebang、编码声明、许可证、格式化或静态分析指令（如 `noqa`、`type: ignore`、`pyright`）、配置格式必需内容，以及正则、字符串或数据载荷中的注释字符。

清理必须以逐个文件审查为准，不能用会删除字符串、YAML 值或 Shell/PowerShell 语义的全局替换。清理不改变任何 Python AST、配置键值、容器命令、网络策略或测试断言。

## 无用文件处理

只删除位于仓库根目录、命名和内容均能确定为本次或历史 pytest 临时产物、pytest cache、Ruff cache、UV cache 或测试任务临时目录的未跟踪目录。删除前逐一列出绝对路径并确认它们不受 Git 跟踪；遇到权限拒绝、来源不明或含业务资料的目录时保留并报告。

不把未跟踪的 `handoff*.md`、架构文档或 `.env` 视为无用文件，也不将它们纳入公开同步。

## 发布与验证

同步前执行敏感信息扫描、受影响文件的语法/格式检查、现有非 live 且非 integration 测试，以及 Git diff/状态检查。若任何门禁失败，停止推送并报告失败证据。

提交仅包含本设计文件、注释清理和可能新增的 `.gitignore` 临时目录规则；不混入现有用户改动。推送目标固定为 `origin/master`，推送前再次核对远端 SHA，避免覆盖他人提交。
