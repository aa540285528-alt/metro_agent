# 内部试点身份认证设计

## 目标

为小范围内部试点提供本地管理的用户名密码账号、可即时回收的访问权限，以及由服务端强制执行的按用户数据隔离。

## 范围

首版提供以下能力：

- 账号仅由管理员创建，不提供公开注册。
- 使用用户名和密码登录。
- 两类角色：`admin` 与 `user`。
- 会话状态保存于独立 MySQL 身份库。
- 按用户隔离会话记录，监控页面仅管理员可访问。
- 通过本地初始化命令创建首个管理员。

首版不提供 SSO、邮箱验证、找回密码、多组织租户、委派管理员和细粒度知识库/工具权限。

## 架构

认证作为应用内部的独立模块，使用独立 MySQL 数据库和独立迁移历史。现有 PostgreSQL 继续作为会话历史、Agent Trace 与评测记录的权威存储。认证模块是唯一允许读写 MySQL 身份表的应用组件。

浏览器使用名为 `metro_session` 的随机不透明会话令牌 Cookie。该 Cookie 设置 `HttpOnly`、`Secure` 与 `SameSite=Lax` 属性；服务端仅存储令牌哈希，绝不写入原始令牌或日志。每个受保护接口从 Cookie 解析当前用户，并移除公共 API 中由客户端传入的 `user_id`。

每个有效会话最长存活八小时。禁用用户、显式撤销会话或退出登录后，会话立即失效，因为每次请求都会校验 MySQL 中的用户状态与会话状态。

## 数据模型

### `users`

| 字段 | 用途 |
|---|---|
| `id` | 稳定、不暴露业务含义的用户标识，供应用数据归属校验使用。 |
| `username` | 统一转小写后的唯一登录名。 |
| `password_hash` | Argon2 密码哈希，绝不保存明文密码。 |
| `role` | `admin` 或 `user`。 |
| `is_active` | 被禁用的用户不能创建或继续使用会话。 |
| `created_at`、`updated_at`、`last_login_at` | 账号生命周期时间字段。 |

### `auth_sessions`

| 字段 | 用途 |
|---|---|
| `id` | 服务端会话标识。 |
| `user_id` | 指向 `users` 的外键。 |
| `token_hash` | 浏览器不透明令牌的 SHA-256 或 HMAC 哈希。 |
| `created_at`、`expires_at`、`revoked_at` | 会话生命周期与显式撤销状态。 |

### `auth_audit_events`

| 字段 | 用途 |
|---|---|
| `id`、`occurred_at` | 审计事件标识和发生时间。 |
| `actor_user_id`、`subject_user_id` | 操作者与受影响账号，在适用时记录。 |
| `event_type` | 登录成功/失败、登出、创建用户、重置密码、禁用、启用或撤销会话。 |
| `metadata` | 最小化的非敏感诊断信息；不得记录密码、原始会话令牌、提示词或工具结果。 |

## API 与授权规则

公开认证接口：

- `POST /api/auth/login`：接收用户名和密码，创建会话、设置 Cookie，仅返回安全的当前用户元数据。
- `POST /api/auth/logout`：撤销当前会话并清除 Cookie。
- `GET /api/auth/me`：返回当前已认证用户及其角色。

仅管理员可访问的接口：

- `POST /api/admin/users`：创建用户，设置初始密码和角色。
- `PATCH /api/admin/users/{user_id}`：修改角色、重置密码或启用/禁用账号；禁用账号时撤销其全部活跃会话。
- `GET /api/admin/users`：列出账号，但不得返回密码哈希或会话令牌。

所有聊天与会话接口都要求当前用户身份。服务端从已认证会话推导 `user_id`。`user` 仅能列出、读取、修改和删除持久化归属为自身的会话。监控和评测接口必须要求 `admin`，不得通过查询参数 `user_id` 决定授权范围。

## 初始化与部署

`compose.yml` 新增隔离的 MySQL 服务、命名数据卷与私有网络端点。应用新增 `AUTH_DATABASE_URL`；原有 `DATABASE_URL` 仍只用于 PostgreSQL 业务数据。认证库迁移必须在应用开始接收请求前完成。

首个管理员通过交互式命令创建，例如 `python -m metro_agent.auth.bootstrap_admin --username admin`。命令使用 `getpass` 读取密码，校验用户名和密码策略，生成 Argon2 哈希后写入 MySQL；若用户名已存在则拒绝执行。

试点环境必须部署在 HTTPS 反向代理后。反向代理负责 TLS 终止，仅向外暴露应用端口；MySQL 与 PostgreSQL 只在 Compose 内网可见。开发环境可以通过显式配置关闭 Cookie 的 `Secure` 属性，生产型配置不得关闭。

## 安全与失败规则

- 无效凭据无论账号是否存在，都返回相同的 `401` 响应。
- 登录接口按规范化用户名和客户端地址限流。
- 身份库不可用时，受保护接口必须安全失败并返回 `503`，不允许匿名降级。
- 应用启动时校验身份库连接串、会话签名/pepper 密钥、Cookie 策略和 Argon2 配置。
- 密码、密码哈希、原始会话令牌、授权头、MySQL 连接串均不得进入日志、Trace、Langfuse 载荷或 artifact。

## 验收测试

满足以下条件后方可接受该实现：

1. 全新 MySQL 数据库可以创建首个管理员，并可成功登录。
2. 缺失、畸形、过期、撤销或已禁用的会话访问受保护 API 时均返回 `401`。
3. `user` 访问监控、评测或管理员接口时返回 `403`。
4. 用户 A 即使知道用户 B 的 `thread_id`，也无法读取、修改或删除其会话。
5. 禁用账号会立即使该账号所有已存在会话失效。
6. 登出会使当前会话失效并清除浏览器 Cookie。
7. 数据库记录和应用日志不含明文密码或原始会话令牌。
8. 既有确定性测试继续通过；新增 API 集成测试覆盖登录、登出、授权、隔离、撤销和初始化行为。
